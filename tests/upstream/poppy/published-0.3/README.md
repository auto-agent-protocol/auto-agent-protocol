# Published PAP 0.3 fixtures

Unmodified Company-kit schemas at [commit 6fb46d381ac1b94265795132af13848ec442b6f6](https://github.com/personal-agent-protocol/personal-agent-protocol/tree/6fb46d381ac1b94265795132af13848ec442b6f6/kit/company/schemas), Apache-2.0 (license in the parent directory). `sha256.json` pins each file. The normative [versioned specification](https://github.com/personal-agent-protocol/personal-agent-protocol/blob/6fb46d381ac1b94265795132af13848ec442b6f6/content/versions/0.3/spec.mdx) has SHA-256 `2bf4eaa68041e960f45d2397844d0dc4163d9610698c251d9c97b17b01b16fdd`. This is published 0.3, not draft 0.4 and not AAP 3.1's October 26 guest-token profile.

`poppy-upstream.test.ts` validates baseline examples independently against these files. AAP reader schemas tolerate unknown scope-hint values per the normative text; publisher schemas enumerate known values. Signed-out CIMD requires only `client_id` and `jwks_uri`; unlike the kit it does not require a display name, OAuth auth-method declaration or unused redirect list. Explicit `none` is also valid for signed-out identity; account OAuth separately needs `private_key_jwt`. AAP follows the normative 1–256-character ID syntax and nonempty `jti` instead of the kit’s 22-character minimum; randomness cannot be proved by string length. AAP accepts fractional JWT NumericDates and positive OAuth lifetimes where the kit uses integers. AAP checks HTTPS credentials, OAuth grant conditions and delegated ES256 public-key shape more strictly. Schema success never proves a signature, freshness, random identifiers, replay policy, safe fetching, browser isolation or deployment acceptance.

The parent-directory October 26 fixtures remain in use for frozen AAP 3.1 regression tests. Optional conversation and sign-in extensions are not certified by this fixture subset and must pass the complete pinned specification when advertised.
